## 1. 기존 시스템이 놓치는 주요 원인

- `sepa/setup.py`는 Trend, 베이스20일, ATR비율≤0.75, Dry-up≤0.70, 수축2회를 동시에 요구합니다. 이는 정석 규칙이며 임의 완화하지 않았습니다. 단기5~10일 기회와 다른 목적입니다.
- `sepa/exit.py`는 확인된 최근 스윙 저점에서 버퍼를 빼 손절을 계산합니다. 모든 종목에서 먼 저점을 쓴다는 주장은 하지 않습니다. 실제 MRNA 9/22 저장값은 손절124.2735/위험31.93%로 확인했습니다.

- Sites `worker/index.mjs` 수집은 일반 스크리너를 정석 추세/RS순으로 정렬해 상위12개를 전달합니다. 공격형 전용 피드와 신규 전략은 자동 연결되어 있지 않습니다. 기존 공격형 탭은 별도 피드를 읽지만 추천팀 수집과 동일 경로가 아닙니다. 특정 유료 보고서가 이 이유로 실제 누락했다고 단정하지 않습니다.
- [PR#80](https://github.com/gatbatanic-eng/sepa-screener/pull/80)은 미병합 초안이며 GitHub Pages 오버레이만 변경합니다. Sites/Worker는 별도 코드베이스입니다. 이번 PR은 그 파일을 다시 고치지 않습니다.

## 6. 검증
