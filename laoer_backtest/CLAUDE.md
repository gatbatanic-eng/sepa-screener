## 2. 현재 규칙 (`signal.py`, 설정은 `position.yml`)
1. 변동성 = TQQQ 최근 20거래일 일간 로그수익률 표준편차 × √252
2. 기본 목표 비중 = min(100%, **40%** ÷ 변동성)
3. **추세 규칙:** 나스닥100(^NDX) 50일 평균 < 200일 평균이면 목표 비중 × **0.5**
4. 현재 비중이 목표와 **±10%p** 넘게 차이 날 때만 매매한다. 나머지 현금은 단기국채 ETF(SGOV/BIL 등)에 둔다고 가정한다
5. **분할 진입(진행 중):** 2026-10-27 시작, 5주, 시작 비중 26.7%
   - 매주 (목표 − 26.7%)의 1/5씩만 올린다
   - 이 기간에는 2%p 이상 모자랄 때 매수한다
   - 매도(위험 축소)는 평소 규칙대로 즉시 한다
   - 주차는 신호 기준일로 센다: 1주차 10/27~11/2, 2주차 11/3~, 5주차는 11/24~11/30. 12/1부터는 일반 규칙이다

아침 보고 절차:
1. master 를 fetch 해서 `signal/latest.md`와 `position.yml`을 읽는다.
2. "종가 기준" 날짜가 직전 미국 거래일이 아니면 GitHub 예약 실행이 밀린 것이다. 이런 일이 자주 있다.
   - Actions 실행 목록을 확인한다.
   - `laoer_signal.yml`을 master 에서 workflow_dispatch 로 실행하고, 커밋되면 다시 읽는다.
3. "추세:" 줄이 없거나 `data/NDX.csv`가 `TQQQ.csv`보다 오래됐으면, 나스닥 수집이 실패해 추세 규칙이 빠졌다고 알린다.

주의:

## 5. 사용자가 체결을 알려주면
1. `git fetch origin master && git checkout -B claude/laauer-backtest-engine-rh05oi origin/master`
2. `position.yml`의 `shares`, `cash_usd`를 고친다. 주석에 평단과 날짜를 남긴다.
   - 현금 = 기존 현금 − 매수금액(+ 매도대금)
3. 로컬에서 `python -m laoer_backtest.signal`로 확인하고 `python -m unittest tests.test_laoer_backtest`(8개)를 돌린다.
4. 커밋 → push → PR → 병합한다. 사용자는 매번 PR 병합을 원했다.
   - 병합 후 push 트리거가 다시 계산해서 #108에 올린다.

git 주의:
- 이 브랜치에 다른 자동화(성과 원장 등)가 커밋을 섞어 넣는 일이 있다. 충돌이 나면 `laoer_backtest/` 외 자동 생성 파일은 master 쪽(`--theirs`)을 쓴다.
- force push 는 거부된다. 원격 브랜치가 앞서 있으면 merge 로 맞춘다.
- push 후에는 신호 워크플로가 브랜치에 커밋을 하나 더 얹는다. 병합할 때 `expectedHeadSha`를 원격 최신으로 다시 확인한다.
