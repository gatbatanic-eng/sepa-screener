# 골든코드 — 2-2-2 주도주 선정·종가베팅 연구

사용자가 "시황정리", "분석", "종가베팅"을 요청하면 이 문서의 절차로 진행한다.
규칙 정본은 `RULES.md`(2-2-2, 재료 검증, 수급, 위험관리, 13항 전체 시장 탐색)다. 요청 때마다 먼저 읽는다.

## 원칙
- 별도 사이트·스크리너를 만들거나 기존 코드를 고치지 않는다. 이 폴더의 수집기와 기록만 다룬다.
- 데이터는 요청 때마다 실제 조회한다. 없는 값은 채우지 않고 '미확인'으로 쓴다.
- 이 세션(클라우드 샌드박스)은 네이버·KRX·NHPLUG에 직접 접속하지 못한다(프록시 403). 시세는 GitHub Actions가 수집해 데이터 브랜치에 올린 파일을 GitHub MCP로 읽는다.
- 백그라운드 감시·자동 알림이 있는 것처럼 말하지 않는다.

## 데이터 경로
| 용도 | 위치 | 비고 |
|---|---|---|
| 정밀 시세(감시 표본) | `nhplug-live-data` 브랜치 `research/nhplug/intraday/latest.json` | NHPLUG REST, 초당 5회. 한 바퀴 지연 확인 필수 |
| 시장 전체 순위(후보 발견) | `goldencode-live-data` 브랜치 `research/goldencode/` | 네이버 금융. 지연 순위, 발견용 |
| 순위 경로 점검 결과 | `goldencode-live-data` `research/goldencode/probe/rankings.json` | 어떤 경로가 되는지 |

NHPLUG에는 순위·조건검색 API가 없다(`research/nhplug/docs/krstock/openapi.json` 확인). 순위는 NHPLUG 밖에서 받는다.

## 분석 절차
1. 데이터 점검: 현재 KST 시각, 각 파일의 `generatedAt`과 종목별 `quoteTime`, `status`, 요청·수신 수, 지연 초.
2. 시황: 지수, 상승·하락 분포, 거래대금 집중, 수급, 강한 업종.
3. 발견: 순위 파일의 조건별 목록을 합집합으로 모아 중복 제거. 확보 범위와 누락 경로를 먼저 보고.
4. 압축·검증: 재료(공시·뉴스 원문), 가격 구조, 유동성.
5. 2-2-2 분류 → 0순위 → 진입 검토/보류/제외.
6. 최종 판단 직전에 후보만 NHPLUG로 재조회. 5분 이상 지연이면 최종 진입 판단 보류.
7. 확정 기록을 `records/YYYY-MM-DD.md`에 남긴다(`records/TEMPLATE.md`).
