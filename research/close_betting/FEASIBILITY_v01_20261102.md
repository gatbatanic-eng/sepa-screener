KRX와 NXT/통합 거래량을 섞지 않는다. 첫 버전은 KRX 종가 기준. '전시장 최강' 대신 '검사한 감시 유니버스 내 후보'로 표시한다. 전시장 목표라면 당일 급등 신규 유입을 찾는 전종목 탐색 또는 순위 공급원을 추가해야 한다.
당일 누적 거래량을 전일 하루 전체와만 비교하지 말고 동일 시간대 이력 대비 상대 거래량을 쌓는다. 이력이 없으면 해당 지표 사용 불가를 명시한다.

## 권고 운영 설계 (미구현 목표)
1. 장전: 종목마스터/일봉/ATR/실적/이벤트 캐시. 장중 모든 후보마다 400일봉 재다운로드 금지.
2. 14:30~15:05: 광역 탐색을 반복해 유동성·강도 후보 30~50개 확보; 당일 신규 강세종목 포함.
3. 15:05~15:15: 5분봉·시장/업종 대비·VWAP·뉴스/공시·위험 필터로 10~20개 압축.
4. 15:15~15:18: 후보 상세자료 완성; 최종 3~5개와 예비후보를 고름.
5. 15:18~15:19: 최종 후보 가격/호가 재검증, 데이터 컷오프와 점수 고정.
6. 15:19~15:19:30: 결정적 템플릿으로 작성·전달. 실제 도착 15:20 이전 목표. LLM 장애 시 수치 템플릿 전달.
7. 15:20~15:30: 별도 선택 기능으로 예상체결가 기반 취소/가격 상한 재검토. 최초 브리핑의 미래정보로 소급 사용하지 않음.
15:20는 KRX 종가 단일가 시작. 15:20 이전에는 확정 종가를 알 수 없다. 최대 허용 진입가격과 취소조건을 적고 확정 종가 체결을 보장하지 않는다.

시간 예산 추정: 관측418초/168종목은 상세수집까지 포함한 혼합 평균 약2.49초/종목이다. 이를 후보20개로 단순 환산하면 약50초이나 실측 성능 보장값이 아니다. 상세수집과 최종 현재가 갱신을 분리한 10/20/50종목 실측이 필요하다.
NH 공식 문서는 REST 초당5회 수준, WS 동시2개 채널/채널당30건 구독을 안내한다. 이것이 실제 왕복응답 0.2초나 무제한 병렬처리를 뜻하지 않는다. 기존 작업과 합산 유량/토큰 관리 필요.

## 스케줄·전달
GitHub 공식 문서는 cron 지연/누락 가능성을 명시한다. 15:18에 새 Actions를 예약하는 구조로 15:20 도착을 보장하지 않는다.
기존 장시간 worker가 살아 있으면 내부 시각으로 마감 작업을 수행하는 시범 운영은 가능하나, 운영용은 14:30 이전 기동·상태감시·복구 가능한 상시 서버/전용 실행 환경이 유리하다.
보고서 생성시각, 게시시각, 사용자 도착시각은 분리 측정. Git push/Pages 배포시간도 전송 지연에 포함한다. 전달 채널 구현이 필요하고 이 점검에서는 예약·구독·발송을 활성화하지 않았다. 대화만으로 상시 실행·정시 푸시를 보장하지 않는다.

## 선별 원칙과 합격 기준 (제안)
- 첫 버전은 추세 지속/추세 눌림의 종가 진입 중심. 초기 전환·역추세는 별도 계열로 분리.
- 위험/데이터 탈락 필터를 먼저 적용. 이후 시장 대비 강도, 오후 지속성, 거래대금, VWAP 유지, 동종업종 동반강세, 진입가격 대비 손절거리를 비교. 상승률 순위만으로 선정하지 않음.
- 0~3종목, 적격 없음 허용. 미검증 점수를 승률/확률로 부르지 않음.
- 출력: 코드/이름, 근거/반대근거, 공급원 시각·수신시각, 현재가, 최대 진입가, 취소조건, 손절/청산 규칙, 데이터 결손, 최종 판단.
- 최종 가격·호가 나이60초 이내 목표, 120초 초과 시 후보 제외(시범 중 성능/거래빈도 근거로 규칙 동결). 필수 데이터 결손·지연은 관망 처리, 전일 결과 대체 금지.
- 5~10거래일 기술 시범으로 요청성공률, 최신성, 후보 커버리지, p50/p95 처리시간, 15:20 도착률, 키 충돌을 기록. 성능 목표 예시 도착률95% 이상; 이 표본만으로 장기 신뢰성 입증 아님.
- 기술 합격 후 데이터 감사 → 규칙 동결 → 시점이 맞는 백테스트 → 독립 검증 → 전진검증. 일봉만으로 15:19 신호를 복원할 수 없음.
- 동일 15:19 의사결정에서 지금매수/눌림대기/돌파대기/관망 비교. 청산은 익일시가 또는 익일 정해진 시각 등 사전 고정. 비용후 기대값·손익비·MDD·체결률·놓친상승·갭손실을 기록. 승률60% 달성 주장은 아직 불가.
- 신규 기술검증용 전략이며 기존 Golden Entry 4전략군 감사/연구 상태를 덮어쓰지 않는다.
